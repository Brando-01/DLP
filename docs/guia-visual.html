Arquitectura de red

Kali y Windows comparten la red Host-only. El participante carga archivos hacia el puerto TCP 3000 del servicio; el receptor inspecciona antes de guardar. La dirección exacta de Kali debe verificarse en su terminal.

Arquitectura de componentes

El navegador consume la API de una única aplicación Node.js. Multer recibe en memoria, el motor calcula la decisión y el servidor escribe archivos permitidos o en alerta, además de sus eventos de auditoría.

Flujo de procesamiento

Con cero puntos se permite; con uno o dos se permite con alerta; con tres o más se bloquea el almacenamiento. Los errores de formato, tamaño o UTF-8 son distintos de una decisión de bloqueo por contenido.

Secuencia de una transferencia

Primero se analiza, después se guarda el archivo cuando corresponde, se registra la decisión y se responde. El navegador solicita después los eventos recientes para refrescar la tabla.

Cómo explicarlo en una demostración

  1. Windows ejecuta el servicio y Kali abre el portal a través de la red Host-only.
  2. Se selecciona un archivo ficticio TXT, CSV o JSON y se pulsa «Analizar y transferir».
  3. El servidor valida la carga y aplica siete reglas, que aportan puntos una vez cada una.
  4. Con 0 puntos permite; con 1–2 permite con alerta; con 3 o más bloquea el almacenamiento.
  5. Se contrasta el resultado con los eventos, la carpeta de recibidos y la clasificación de referencia.

Una alerta detecta pero permite guardar. Un archivo con datos sensibles puede pasar si las reglas no reconocen su forma de escritura; un ejemplo didáctico puede activar una regla indebidamente. Por eso se evalúan falsos positivos y negativos.

Qué está implementado y qué viene después

La versión actual usa patrones, archivos locales y HTTP. Admite texto UTF-8 de hasta 1 MiB; no dispone de autenticación, cuarentena, análisis antivirus ni lectura PDF/Office. Groq es una ampliación futura para evaluar contexto.

La dirección de Windows 192.168.56.1 se comprobó con ipconfig. La IP exacta de Kali, el estado de la VM y el firewall no se verificaron en esta revisión. El proceso escucha por defecto en 0.0.0.0:3000, es decir, en todas sus interfaces IPv4.

Las cargas inválidas antes del análisis no generan evento DLP. Las escrituras de archivo y auditoría son separadas: si falla la segunda, puede existir un archivo guardado aunque la respuesta sea de error.
